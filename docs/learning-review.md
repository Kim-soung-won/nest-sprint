# 학습 마무리 Q&A

## 시작 시점과 원칙

사용자가 “오늘 여기까지”, “마무리”, “학습 완료”라고 하거나 당일 실습과 리뷰가 끝나면 마무리 Q&A를 시작한다. 단순 파일 설정이나 문서 수정 작업만 끝났을 때는 평가를 시작하지 않는다.

- 오늘 실제로 학습한 범위와 코드·실험 결과를 먼저 확인한다. 미학습 내용을 평가하지 않는다.
- 기본 분량은 핵심 질문 3개, 약 5~10분이다. 답변에 따라 짧은 꼬리질문을 추가하되 사용자가 줄이거나 중단할 수 있다.
- 질문은 한 번에 하나만 제시하고 답변을 기다린다. 대화 중 질문 도구를 사용할 수 있으면 자유 답변 방식으로 묻는다.
- 모범답안, 핵심 정답, 채점 기준의 구체적인 정답 요소를 질문과 함께 공개하지 않는다. 사용자의 설명을 먼저 듣는다.
- 사용자가 바로 종료하거나 나중에 하기를 원하면 존중한다. 남은 질문과 다음 재개 지점을 기록하며 완료나 0점으로 처리하지 않는다.

## 질문 구성

세 가지 관점으로 질문한다. 용어 암기보다 자신의 말로 설명하고 관찰 결과에 연결하는 능력을 본다.

1. **설명:** 오늘 배운 핵심 동작이 왜 발생하는지 설명하도록 한다.
2. **예측:** 코드나 실행 조건을 한 가지 바꾸고, 실행 전에 결과와 이유를 예측하도록 한다.
3. **진단·적용:** 실제 서버 증상에 대해 가설, 확인할 지표·실험, 수정 방향을 제안하도록 한다.

실제 작성한 코드나 측정값을 질문에 활용한다. 예측 문제의 실행 맥락과 조건을 명시하고, 보장되지 않는 출력 순서를 하나의 정답으로 채점하지 않는다.

## 답변과 피드백 진행

1. 첫 답변을 듣고 타당한 설명과 빠진 근거를 구분한다. 말투나 답변 길이로 평가하지 않는다.
2. 모호하면 “그 판단을 확인하려면 어떤 실험을 할까요?”처럼 중립적인 꼬리질문을 한다.
3. 막히면 작은 힌트를 주고 다시 설명할 기회를 준다. 힌트 전 답변과 힌트 후 답변을 구분한다.
4. 오개념이 확인되면 답변 기회를 준 뒤 짧게 교정한다. 바로 비슷한 문제를 풀었다고 독립적으로 이해했다고 판단하지 않는다.
5. 질문별 결과를 남기고 다음 질문으로 넘어간다. 세션 끝에 확인된 강점, 복습할 개념 1~2개, 다음 행동을 알려준다.

## 이해도 기준

각 질문에 아래 수준을 적용한다. 첫 답변의 수준과 도움 후 상태를 별도로 기록한다.

| 수준 | 관찰 기준 |
| --- | --- |
| 0 · 재학습 필요 | 실제 답변에서 핵심 동작을 잘못 설명하거나 아직 설명하지 못한다. |
| 1 · 부분 이해 | 결과나 용어는 알지만 원인·조건 설명에 핵심 공백이 있다. |
| 2 · 이해 확인 | 해당 조건에서 원인과 결과를 독립적으로 설명하고 실험 근거에 연결한다. |
| 3 · 응용 확인 | 달라진 조건에도 설명을 적용하고, 한계와 검증 방법을 타당하게 제시한다. |
| 미평가 | 미응답, 중단, 미학습 또는 근거 부족으로 판단을 보류한다. |

총점이나 백분율보다 질문별 근거를 우선한다. 총점을 요청받으면 응답한 질문 수와 가능한 최대 점수를 함께 밝히고, 전체 Node.js 역량 점수로 일반화하지 않는다. 실습 성공과 설명 능력은 별개의 증거다.

## 기록과 다음 세션 연결

해당 docs/daily/day-XX.md의 Q&A 영역에 실제 질문과 답변 요약, 근거를 기록한다. 사용자가 말하지 않은 답변이나 측정 결과를 만들어 채우지 않는다. 원문이 아닌 요약은 요약임을 명시한다.

Notion에는 학습 지침의 기존 페이지 갱신 절차에 따라 같은 결과를 반영한다. 접근이 불가능하면 로컬 기록에 미반영 상태를 남긴다. 완료 기준과 대응하는 답변이 확인된 항목만 체크하며 Q&A 미완료를 실습 미수행으로 취급하지 않는다.

다음 세션 시작 시 지난 약점 중 하나를 짧게 다시 묻는다. 이전 답을 외웠는지보다 조건을 바꿔 설명할 수 있는지 확인한다.
