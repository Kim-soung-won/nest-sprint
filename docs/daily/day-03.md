## 학습 방식과 재개 지점 · 2026-11-13

- 사용자 요청: 직접 코딩을 계속 수행하는 방식보다 개념적인 공부가 중요하므로 이를 명시한다. 학습 지침에 개념 우선, 직접 구현은 사용자 희망 시 진행, 코드·실험은 이해를 돕는 수단이라는 원칙을 반영했다.
- 지금까지 다룬 개념: req.url은 출발지가 아닌 요청 경로·쿼리이며, node:http에는 기본 req.body가 없다. 요청 본문을 data의 Buffer 조각으로 받고 end에서 합친다. 등록과 수신 완료를 구분하고, res.end는 JavaScript 함수 자체를 종료하지 않음을 확인했다.
- 사용자 확인: /health 응답, 업로드 본문 바이트 수 응답이 동작했다고 보고했다. UTF-8의 '안녕'은 2가 아니라 6바이트라고 스스로 정정한 뒤 실행 결과도 확인했다.
- 다음 개념: 업로드한 바이트를 파일에 저장하는 흐름과 저장 경로의 의미. 경로 검증 코드를 직접 작성하라는 과제는 이어가지 않는다. 본문 수신 완료, 파일 쓰기 완료, HTTP 응답 시점의 차이를 중심으로 설명한다.
- 파일 저장·크기 제한·파일 목록·다운로드는 아직 구현 및 검증하지 않았다. 마무리 Q&A는 미진행이다.
- 에이전트 확인(2026-11-13, macOS arm64, Node.js v22.23.1, `npm run server`): GET /health → 200 ok, POST /upload?name=a.txt 본문 '안녕' → 200 6, name 없는 POST /upload → 400, 그 외 경로 → 404.
- Notion 반영(2026-11-13): 학습 페이지에 학습 방식 변경, 진행 상태, 'Day 3 진행 기록' 절과 재개 지점을 저장하고 재조회로 확인했다. Day 3 일정 완료와 최종 체크리스트는 변경하지 않았다.
